# 顧客CSV（data/）

`data/customers.csv` は実顧客の情報を含むため **Git対象外** です（`.gitignore` で `*.csv` を除外）。
Gitに含まれるのは架空のひな形 `customers.example.csv` と、公開地点デモ用の `customers.demo.csv` だけです。

## 必要な列

列名は文字化けを避けるため **半角英字** です（1行目に記載。大文字/小文字・前後の空白は区別しません）。

| 列名 | 必須 | 内容 | 例 |
| --- | --- | --- | --- |
| `customer_code` | ○ | 顧客コード。重複不可（全角/半角・大文字/小文字を正規化した後も重複不可） | `C001` |
| `customer_name` | ○ | 顧客名。検索・表示に使う名称 | `山田株式会社` |
| `address` | ○ | 住所。都道府県から番地まで。住所→座標変換（Geolonia）に使うため番地まで正確に | `大阪府大阪市北区中之島1丁目3-20` |

- 3列とも全行で空欄不可です。空欄・列数の不一致・コード重複があると読込時にエラーになり、行番号が表示されます（空行は無視）。
- 任意列 `latitude`（緯度）・`longitude`（経度）を追加すると、その顧客は住所検索をせず登録座標で計算します（例: `34.6268`, `135.6013`）。両方入力するか両方空欄にしてください。住所が見つからない顧客だけ入力すればOKです。
- 上記以外の列（例: `memo`, `staff`）を追加しても構いません。読込時は無視されます。
- 列の順番は自由ですが、列名の重複は不可です。
- 旧形式の日本語列名（`顧客コード,顧客名,住所`）は使えません。1行目を上記の英字に書き換えてください（2行目以降の中身は日本語のままで構いません）。

```csv
customer_code,customer_name,address
C001,山田株式会社,大阪府大阪市○○区○○1-2-3
C002,有限会社山田,東京都○○区○○4-5-6
```

座標を登録する場合：

```csv
customer_code,customer_name,address,latitude,longitude
C001,山田株式会社,大阪府大阪市○○区○○1-2-3,,
C002,有限会社山田,東京都○○区○○4-5-6,35.6812,139.7671
```

## 保存形式

- 文字コード: **UTF-8**（BOM付き・なしどちらも可）を推奨。
  - ExcelでUTF-16の「Unicode テキスト（タブ区切り）」で保存したファイルも読めます（BOM付きUTF-16・タブ区切りを自動判別）。
  - Shift_JIS は読めません。
- 区切り: カンマ `,`（UTF-16のタブ区切りも可）。値にカンマや改行を含む場合はダブルクォート `"` で囲む。
- ファイル名・場所: `data/customers.csv`（別の場所を使う場合は `from_to.py --customers <パス>`）。
- Excel で保存する場合は「名前を付けて保存 → **CSV UTF-8（コンマ区切り）(*.csv)**」を選ぶ。
  単なる「CSV（コンマ区切り）」は Shift_JIS になるため不可。
- 顧客コードが `0003` のように0始まりの場合、Excel で開くと `3` に変わることがあります。
  コード列を「文字列」形式にしてから入力・保存してください。

## 初回作成と保管

1. `mac/setup.command` / `windows\setup.bat` を実行すると、`customers.csv` が無い場合に限り `customers.example.csv` からコピーされます（既存ファイルは上書きしません）。
2. 中身を実際の顧客データに置き換えます。
3. Gitには入らないため、**バックアップは別途**（社内共有ドライブ・暗号化したクラウドストレージ等）で管理してください。
   別PCへ導入する場合も、このファイルだけは個別にコピーします。
