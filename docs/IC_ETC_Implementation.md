# IC自動候補とETC2.0参考料金（2026-10-20実装）

## 現在使える機能

通常のstart.command/start.batから、住所間の経路計算後に入口・出口ICの自動候補と経由道路を表示する。ETC2.0参考額を取得する前にICを確認・修正できる。候補不明/同名ICは名称・読み・7桁コードで検索し、県と道路を見て選択する。車種は普通車/軽・自動二輪/中型/大型/特大から選ぶ。

Geoapifyの追加情報は `details=instruction_details,route_details&lang=ja`。既存のbalanced/free_flowと端点200m検証は維持する。route_detailsには追加クレジットが発生するため、無料枠の使用量に含まれる。詳細が不足・不正ならIC未判定とし「高速なし」「無料」にしない。

高速・有料道路区間はtoll属性またはmotorway分類の連続区間として検出する。区間ごとに入口/出口の座標と一般道を含む累積所要秒数を保持する。一般道を挟む複数区間も個別に表示・検索する。

## IC座標の無料データ源

国土交通省の国土数値情報「高速道路時系列・2025年版」の接合部データを使用する。最新公表版として2026-10-20に確認した原本は約8.3MB、基準日は2025-12-31。初回のIC照合時に取得しstate/ic-catalogへ原本ZIP/GeoJSONとURL・SHA256・取得日時を保存する。Dockerや全国道路の前処理は不要。経路の座標や顧客情報を国交省へ送信しない。

2025年現況として有効な接合部だけを使う。過年度の廃止/変遷を含む時系列利用は行わない。一般IC/スマートICを候補にし、JCTやSA/PAを乗降ICと取り違えない。NEXCO現行ICマスターの名称と突き合わせ、コードと道路・県・出入口の注意を表示する。

自動判定は利用者確認前の候補である。経路接続点から1.5km以内の経路部分と、IC位置の経路からの距離180m以内を照合し、接続点から1.6kmを超える地点は除外する。道路名一致と候補間の差で曖昧さを判定する。出入口方向の明示制限に反する候補は除く。道路接続グラフによる厳密証明や、全ICでの正解保証ではない。複数候補/不明の場合は先頭を採用しない。新設ICや別名など元データの差は手動選択で補える。

通常起動で取得したICデータを再利用する。`python update_ic_data.py --force` は国交省2025年原本とNEXCO現行JSを再取得する。国交省の年度は明示固定で、新年度を自動採用しない。新年度への変更時はスキーマ/対象年/利用条件を確認する。

出典：国土数値情報「高速道路時系列・2025年現況」（国土交通省）を加工して作成（CC BY 4.0）。原本ページ：https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N06-2025.html

## NEXCO料金取得

添付Architecture v3を基本に `src/nexco_toll` を実装。`TollService.search(from_ic,to_ic,vehicle_type=...,departure_at=...)` から名称解決・ICコード・取得・料金/詳細解析をまとめて呼べる。通常ETC/現金の代用はしない。IC原本JSはstate/nexcoに改変せず保存し、SQLite化しない。7日以内はハッシュ検証済み原本を再使用し、失敗した更新で旧原本を壊さない。JSをコードとして実行しない。

実ページは料金を動的取得していたため、同サイトの公式JSが利用する公開JSONP `/route_ajax/mk_route.php` を読み取り、`routecallback({...})` のJSON部分だけを解析する。これは文書化された安定APIではなく、サイト変更で停止し得る。対象ホスト固定、1秒以上の間隔、容量上限・タイムアウト・リダイレクト禁止、自動再試行なし。料金キャッシュは無効。

最大3つの実在候補を公式の時間順で返す。概要と詳細のNodePoint・日時・距離・時間・ETC2.0額を照合し、ルートの混線を検出する。通過IC/JCT、道路、区間距離・時間をCUI表示する。SA/PA案内は経路地点に混ぜない。詳細が途中までなら不完全と表示し、欠損料金を0円にしない。物理的に通過するすべてのICを列挙したとは説明しない。

出発日時は住所からの出発。既定は土日祝を除く翌営業日09:00（JST）。NEXCOには各入口までのGeoapify累積時間を加えた時刻を最も近い分へ丸めて送る。応答の実検索日時が要求と一致しなければ料金を保留する。取得日時と検索日時は別々に表示する。

料金は1台あたりの参考額。Geoapifyは住所間、NEXCOはIC間で別経路になり得る。経路一致・採用を確定する機能と合計加算は今回含めない。手動でICを変更した場合、元の経路接続点の到達予定時刻を使う参考検索であり、変更ICへの経路・所要時間は再計算しない。

継続業務運用の利用条件の確認は残る。スクレイピングの明示禁止がないことを、業務利用許諾取得済みとは扱わない。

## 公開関数とJSON

CUIは既定でHighwayServiceを注入する。Pythonからは `estimate_trip(..., highway_service=HighwayService(state_directory))` でIC候補を付加できる。省略時は従来互換でIC座標の追加通信はしない。Geoapify自体の道路詳細は返る。`highway_information` に区間/道路/候補/入口予定、`toll_results` に明示取得した参考料金を保持し、`to_dict()`でJSON化する。TollServiceは住所・顧客・人件費から独立する。

`from_to.py --no-highways` で国交省/NEXCO取得を省略できる。Geoapify詳細は取得するがIC自動照合は行わない。

## 実機検証と限界

2026-10-20、このMacの通常CUIを起動し、利用者指定の大阪市役所→王寺町藤井の経路で終了0を確認。Geoapify実応答から29,129m、入口候補「高麗橋」、出口候補「藤井寺」、09:00住所出発→09:02入口予定を表示。NEXCOは2026-10-21 09:02/普通車で3経路を返し、各ETC2.0参考額960円を取得。ルート1は高麗橋→えびすJCT→松原JCT→藤井寺、18.7km/20分。これは検証条件付きの参考値であり、将来の確定料金ではない。

IC原本v155は2,290件。国交省接合部原本は2,479地点、実採用は当該年の有効なICだけ。全国の全IC組み合わせを検証したものではない。全国OSRMは再実行していない。

ネットワークなしの検証は200 passed。実保存JSONPから料金と経路を照合し、曖昧名・ルート混線・日時不一致・ETC2.0欠損と0円・不完全詳細・悪い原本更新・リダイレクト/制限・複数高速区間・一般道累積時刻・CUI車種指定・JSON保持を検証。Windowsネイティブ実行は未検証。
