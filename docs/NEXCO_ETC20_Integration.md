# NEXCO ETC2.0連携の補足設計（2026-10-20）

[添付Architecture v3](NEXCO_ETC20_Architecture_v3.md)は原本のまま保存。本書は既存Geoapifyアプリとの接続条件を定める。Web取得・独立モジュール・料金のCUI連携は未実装。

## 相談・承認済み

- ETC2.0だけを返し、通常ETC・現金料金で代用しない。
- 出発時刻の既定値は日本時間09:00。出発日は土日祝を除いた翌営業日を既定とする。CUIで日付・時刻を変更できる。取得日を実際の旅行日とみなさない。
- 日時指定が未実装の間は「サイト既定日時の参考額」。実際の検索日時を読み取れなければ「不明」。9:00をサイトへ送信していないのに9:00の料金と表示しない。
- Geoapifyの渋滞なし推定とNEXCOの検索日時を区別する。
- Geoapify経路との一致・採用ルートを確認するまで合計へ加算しない。同じICペアだけでは一致とみなさない。先頭/最安ルートを自動採用しない。
- 候補は公式順、最大3件。入口/出口IC、経由道路/JCT、距離、時間、ETC2.0額、検索条件、取得日時、出典URLを確認できるようにする。経路情報が足りなければ未照合の参考表示に留める。

## 実装時の検証・未決事項

- 添付v155原本は今回未取得。件数、配列位置、IC/車種コードを現行サイトで検証する。evalを使わない。
- 実ページ1件で静的/動的取得と料金列・ルート詳細の対応を確認する。添付の参考価格を実測結果として扱わない。
- 初期の料金キャッシュは無効。日時未対応時の取り違えを避ける。TTL導入時は検索日時/条件を含むキー・失効規則を相談する。
- 日時パラメータ、経路照合、一般道を挟む複数高速区間、車種とETC2.0利用の確認、複数台分の加算方式は次の統合実装前に相談する。
- 欠損料金を無料と混同しない。構造変化・制限検出時は停止し手動確認へ戻す。
- 継続的な業務運用の前に利用条件を確認する。文書の採用を利用許諾取得と扱わない。

## 表示

今回のCUIはサマリー、距離/時間、費用内訳、地点、条件、住所照合/出典の順に整理する。燃料費の未計算と通行料金の対象外を区別し、計算式は変更しない。

将来の料金表示は「ETC2.0参考額・合計未反映」を明記する。経路/条件の確認と採用後だけ合計へ反映する。未実装機能を現在使える機能として表示しない。


## 出発日時の入力（2026-10-20実装）

- 既定は日本時間の現在日付から明日以降の最初の営業日、09:00。土日・日本の国民の祝日、振替休日、祝日に挟まれた休日を除外する。会社独自の休業日は含めない。
- CUI最終確認の「2. 内容を修正 → 4. 出発日・時刻」からYYYY-MM-DD/HH:MMで変更可能。空Enterは現在の値を保持。手入力なら土日祝も選択できる。
- TripRequest/EstimateResult.departure_atへタイムゾーン付き日時を保持し、JSONではISO8601で返す。既存呼出しで省略した場合はNoneとし、CUI起動時だけ既定を設定する。
- 未実装のNEXCO日時パラメータへ送ったことにしない。Geoapifyは引き続きfree_flowであり日時は送信しない。
- jpholiday==1.0.3を使用。2026/2027年の公式公表の範囲を確認。2028年以降は予測である旨をCUIに表示し、制度変更時は依存版・内閣府情報を再確認する。
- 12件の追加検証を含め172 passed。土日、祝日を含む連休、振替休日、国民の休日、年越し、UTC/JST境界、入力エラーと編集、JSON保持を確認。実料金検索は未実施。
